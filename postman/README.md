# Real Bite Server — Postman Local Mode Workspace

A Postman Local Mode workspace: collections and environments live as plain files in this
folder, versioned with the rest of the repo.

## Real format (confirmed against this Postman install)

Local Mode's on-disk collection format is **one directory per collection**, not a single
file. Each collection root, and each folder inside it, carries a `.resources/definition.yaml`
naming its `$kind`; each request is its own `<name>.request.yaml` file:

```
collections/
  Real Bite Server/
    .resources/definition.yaml       # $kind: collection
    Health/
      .resources/definition.yaml     # $kind: folder
      Liveness.request.yaml
      Readiness.request.yaml
    Geo/
      .resources/definition.yaml     # $kind: folder
      List countries.request.yaml
      List states.request.yaml
      List cities.request.yaml
      Search (picker).request.yaml
      Resolve coordinates.request.yaml
```

A request file:

```yaml
$kind: http-request
url: "{{baseUrl}}/geo/countries?limit=50"
method: GET
order: 1790200000003
```

This shape is copied from `collections/v1/Live health.request.yaml` — the collection Postman
itself generated in this workspace — so it's known to be exactly what this Postman build
expects. **A single flat `*.postman_collection.yaml` file (what an earlier pass here used) is
not recognized by Local Mode and will not show up in the sidebar.**

Environments and globals stay flat single files (`environments/*.environment.yaml`,
`globals/workspace.globals.yaml`) — that shape was already correct, since
`workspace.globals.yaml` was generated by Postman before any of this was touched.

## Files

- `collections/Real Bite Server/` — the real collection (7 endpoints, 2 folders: Health, Geo)
- `collections/v1/` — a one-request test collection created from inside Postman while
  diagnosing why collections weren't appearing. Harmless; delete it from Postman's sidebar
  (or `rm -rf` the folder) whenever you don't need it anymore.
- `environments/*.environment.yaml` — dev / staging / production, one `baseUrl` each
- `globals/workspace.globals.yaml` — variables shared across all environments
- `postman.workspace.json` — workspace metadata (only needed if you import rather than use
  Local Mode directly)

## Getting Started (Local Mode)

1. **Open Postman** → Settings → enable **Local Mode**
2. Point it at this folder: `codebase/real-bite-server/postman`
3. The **Real Bite Server** collection appears in the sidebar with Health and Geo folders
4. Pick an environment from the top-right dropdown (`Development (Local)`, `Staging`,
   `Production`)
5. Open a request, click **Send**

If nothing appears after pointing Local Mode at this folder, check that Postman is reading
the workspace **root** (`postman/`), not `postman/collections/` — the root is what Local Mode
expects, and it discovers `collections/`, `environments/`, `globals/` etc. beneath it.

## Adding a New Endpoint

Whenever an endpoint is added, removed, renamed, or its params change, update the collection
in the same change:

1. Add/edit the `<name>.request.yaml` file under the right folder (create a new folder with
   its own `.resources/definition.yaml` — `$kind: folder` — for a new controller)
2. Match the shape above: `$kind: http-request`, `url` (raw, query string inlined), `method`,
   `order` (any increasing integer — timestamp millis is fine)
3. Commit the new/changed files alongside the controller change

## Notes

- **Bengaluru coordinates**: `lat=12.9716, lng=77.5946` — the only `is_launched=true` city
- **Cursor param**: opaque base64url JSON; don't hand-edit it
- Query params are baked into the raw `url` string (`?limit=50` etc.) rather than a separate
  `query` array, matching the Postman-generated sample this format was copied from

## Keeping It in Sync

The reference is always `src/**/*.controller.ts`. If this drifts, walk each controller's
`@Get()`/`@Post()`/etc. and add or fix the matching `.request.yaml` file.
